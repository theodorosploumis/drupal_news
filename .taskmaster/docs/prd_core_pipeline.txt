# Core Data Pipeline PRD

<overview>
## Problem Statement
Drupal community updates are scattered across multiple RSS feeds and web pages. Developers need a reliable, automated way to collect, normalize, and deduplicate Drupal news from official sources with proper timezone handling (Europe/Athens).

## Target Users
Drupal developers and site maintainers who need weekly digests of:
- Core and module releases
- AI/automation integrations
- Canvas/Admin UI updates
- New contributed modules (excluding sandbox projects)

## Success Metrics
- 100% verified drupal.org sources
- Zero duplicate entries in output
- All entries have direct source links
- Data fetched within 20 seconds per source
- Cache hit rate > 60% for repeated fetches
</overview>

<functional-decomposition>
## Capability Tree

### Capability: RSS Feed Ingestion
Extract and normalize data from Drupal RSS feeds

#### Feature: RSS Fetch
- **Description**: Fetch RSS feeds with timeout and retry logic
- **Inputs**: RSS URL, timeout config, retry count
- **Outputs**: Raw feed data or error
- **Behavior**: HTTP GET with user-agent, respect timeouts, retry on failure

#### Feature: RSS Parse
- **Description**: Parse RSS XML into normalized data structures
- **Inputs**: Raw RSS feed data
- **Outputs**: List of normalized feed items
- **Behavior**: Extract title, link, description, pubDate; filter sandbox URLs

#### Feature: RSS Date Normalization
- **Description**: Convert RSS pubDate to Europe/Athens timezone
- **Inputs**: RSS pubDate string, timezone config
- **Outputs**: Normalized datetime object
- **Behavior**: Parse multiple date formats, convert to target timezone

### Capability: Web Page Scraping
Extract structured content from HTML pages

#### Feature: HTML Fetch
- **Description**: Fetch HTML pages with proper headers
- **Inputs**: Page URL, HTTP config
- **Outputs**: Raw HTML content
- **Behavior**: HTTP GET with timeout, retries, custom user-agent

#### Feature: Content Extraction
- **Description**: Extract relevant content from HTML using readability
- **Inputs**: Raw HTML, selectors config
- **Outputs**: Structured page data (title, content, links)
- **Behavior**: Use readability-lxml for main content, BeautifulSoup for parsing

#### Feature: URL Filtering
- **Description**: Filter out non-Drupal and sandbox content
- **Inputs**: List of URLs
- **Outputs**: Filtered URL list
- **Behavior**: Exclude URLs with /sandbox/, verify drupal.org domain

### Capability: Data Normalization
Standardize data from multiple sources

#### Feature: Schema Normalization
- **Description**: Convert diverse inputs to unified schema
- **Inputs**: Raw RSS/page data
- **Outputs**: Normalized item dict with standard keys
- **Behavior**: Map source fields to: title, url, description, date, source_type

#### Feature: Deduplication
- **Description**: Remove duplicate entries across sources
- **Inputs**: List of normalized items
- **Outputs**: Deduplicated item list
- **Behavior**: Hash-based dedup on (title, url) pairs

#### Feature: Timeframe Filtering
- **Description**: Filter items by date range
- **Inputs**: Items list, days count, timezone
- **Outputs**: Filtered items within timeframe
- **Behavior**: Compare item dates against current date minus N days

</functional-decomposition>

## Module Definitions

### Module: rss_reader
- **Maps to capability**: RSS Feed Ingestion
- **Responsibility**: Fetch and parse RSS feeds from drupal.org
- **Exports**:
  - `fetch_rss(urls, since, tz, cache)` - Fetch and parse RSS feeds
  - `parse_feed_item(entry)` - Parse single RSS entry
  - `normalize_date(date_str, tz)` - Convert date to timezone

### Module: webpage_reader
- **Maps to capability**: Web Page Scraping
- **Responsibility**: Scrape and extract content from HTML pages
- **Exports**:
  - `fetch_pages(urls, since, tz, cache)` - Fetch page content
  - `extract_content(html)` - Extract main content from HTML
  - `filter_drupal_urls(urls)` - Filter valid drupal.org URLs

### Module: data_cleaner
- **Maps to capability**: Data Normalization
- **Responsibility**: Normalize and deduplicate collected data
- **Exports**:
  - `normalize_items(items)` - Convert to standard schema
  - `dedupe(items)` - Remove duplicates

### Module: utils/timebox
- **Responsibility**: Date and timezone handling
- **Exports**:
  - `get_cutoff_date(days, tz)` - Calculate cutoff date
  - `parse_date(date_str, tz)` - Parse date string to datetime
  - `is_within_timeframe(date, days, tz)` - Check if date in range

### Module: utils/dedupe
- **Responsibility**: Deduplication algorithms
- **Exports**:
  - `dedupe_by_hash(items, keys)` - Hash-based deduplication
  - `generate_item_hash(item, keys)` - Create item hash

### Module: utils/html_norm
- **Responsibility**: HTML parsing and normalization
- **Exports**:
  - `extract_text(html)` - Clean text extraction
  - `parse_links(html)` - Extract all links
  - `sanitize_html(html)` - Remove scripts/styles

### Module: utils/io_safe
- **Responsibility**: Safe file and network I/O
- **Exports**:
  - `safe_fetch(url, timeout, retries)` - HTTP fetch with error handling
  - `safe_write(path, data)` - Write file with error handling

</structural-decomposition>

## Critical Test Scenarios

### RSS Reader
**Happy path**:
- Fetch valid RSS feed, parse all entries
- Expected: List of normalized items with correct dates

**Edge cases**:
- Empty RSS feed, malformed XML, missing fields
- Expected: Return empty list or partial data, log errors

**Error cases**:
- Network timeout, 404, invalid URL
- Expected: Retry logic triggers, fallback to cached data

### Web Scraper
**Happy path**:
- Fetch drupal.org page, extract main content
- Expected: Structured data with title, content, links

**Edge cases**:
- Page with minimal content, no links, special characters
- Expected: Handle gracefully, extract what's available

**Error cases**:
- Connection failure, rate limiting
- Expected: Respect retry limits, log failure

### Deduplication
**Happy path**:
- List with duplicate title+url pairs
- Expected: Single entry per unique (title, url)

**Edge cases**:
- Similar titles, same URL; identical titles, different URLs
- Expected: Keep distinct entries based on hash

## Test Generation Guidelines
- Use real drupal.org URLs for integration tests
- Mock HTTP responses for unit tests
- Test timezone conversion with multiple formats
- Verify no /sandbox/ URLs in output

<architecture>
## System Components
- **RSS Reader**: feedparser for RSS/Atom parsing
- **Web Scraper**: httpx for async HTTP, readability-lxml for content extraction
- **Parser**: BeautifulSoup4 + lxml for HTML parsing
- **Dates**: python-dateutil + pytz for timezone handling

## Data Models

```python
NormalizedItem = {
    "title": str,
    "url": str,
    "description": str,
    "date": datetime,  # Europe/Athens
    "source_type": str,  # "rss" or "page"
    "source_url": str    # Original feed/page URL
}
```

## Technology Stack
- **Python 3.10+**: Modern Python features
- **httpx**: Async HTTP client with timeout/retry
- **feedparser**: RSS/Atom parsing
- **readability-lxml**: Content extraction
- **beautifulsoup4 + lxml**: HTML parsing
- **python-dateutil + pytz**: Date handling

**Decision: httpx over requests**
- **Rationale**: Better async support, modern API, built-in timeout/retry
- **Trade-offs**: Less familiar than requests
- **Alternatives considered**: requests + aiohttp (more complex)

</architecture>

<risks>
## Technical Risks
**Risk**: RSS feed format changes on drupal.org
- **Impact**: High - could break parsing
- **Likelihood**: Low - RSS is stable format
- **Mitigation**: Validate against schema, graceful degradation
- **Fallback**: Log parse errors, return partial data

**Risk**: Rate limiting on drupal.org
- **Impact**: Medium - slower data collection
- **Likelihood**: Medium
- **Mitigation**: Respect robots.txt, add delays between requests
- **Fallback**: Use cached data

## Dependency Risks
**Risk**: feedparser or readability-lxml bugs
- **Impact**: Medium - parsing failures
- **Likelihood**: Low - mature libraries
- **Mitigation**: Pin versions, comprehensive tests
- **Fallback**: Manual parsing fallback

## Scope Risks
**Risk**: Too many sources added, slow fetches
- **Impact**: Medium - longer execution time
- **Likelihood**: Medium
- **Mitigation**: Parallel fetches, aggressive caching
- **Fallback**: Reduce source count, use only RSS

</risks>
